> 概览见 SURVEY.md 〇节，本文件记精确细节与对 Atlas 决策的校验。

## 1. 方法精确细节

### 1.1 两层状态树与执行状态构成

- **底层**：每个动作-观察对 (a, o) 一个原始节点，按执行顺序成链；根到当前节点的路径 = 完整执行轨迹。
- **顶层**：摘要节点，每个对应一个已完成子目标，`cover_nodes` 指针记录其覆盖的底层节点序列。
- **节点字段（Table 2）**：id / content / parent / children / cover_nodes（仅顶层）/ note（仅顶层，诊断笔记）。运行时靠双指针 p_b（底层当前位置）、p_t（顶层当前位置）+ 全局步号 ℓ（单调递增）导航。
- **当前执行状态 S = C + R + H**：
  - **C（压缩态）**= 根→p_t 路径上的摘要序列，**每条带步号**（这是后面 Revise 能定位的前提）；
  - **R（原始态）**= 上次压缩以来累积的底层节点；
  - **H（执行提示）**= p_b 与 p_t 的 children（旁支暴露"试过的其他方向"）∪ 失败诊断笔记 f。

### 1.2 四操作的精确规则（Algorithm 1）

- **Grow(a,o)**：若 p_b 已有 content 完全相同的孩子 → 指针直接推进、复用该节点（天然去重）；否则新建节点挂为孩子。R 追加 (a,o)；H 用当前节点 children 更新。
- **Compress(m)**：两个触发——① agent 标记子目标完成时**主动调用，摘要内容 m 是调用参数**（LLM 现场生成）；② R 超长阈值时系统兜底强制触发。操作：从 p_b 回溯到上一压缩边界（p_t.cover_nodes[-1]）得覆盖集；若 p_t 已有孩子覆盖相同节点集则复用，否则新建摘要节点。然后 R 清空、C 追加（带步号）、H 用新边界 children 更新。
- **Maintain**：紧跟**每次** Compress。`LLM(任务指令, cover_nodes 展平, 摘要内容) → (通过?, 反馈 f)`。通过则放行；不过则 f 写入 p_t.note，返回 (Fail, f, p_t.id)。
- **Revise(f, b)**：由 Maintain 失败触发或 agent 主动调用。双指针回滚到目标步号 b；C 回退、R 清空；H ← 回退位置 children ∪ {f}；后续动作从回滚点**分叉为兄弟分支**——错误段结构性离开活跃路径，但保留在树里。

### 1.3 对 Atlas 有用的机制洞察

1. 压缩只在子目标边界 + 阈值兜底——与我们决策 #2 逐字一致，双系统交叉验证再 +1。
2. **H 的内容来源 = 树的分支结构本身**（兄弟节点）+ 诊断笔记。Atlas 没有树，H 需从"被推翻 Decision 链（reason/evidence）+ 失败子任务记录"合成——这是实现要点，不是障碍。
3. **MAGE 每次压缩把 R 清空** → 上下文前缀在压缩点必然变化，全文无任何缓存友好设计 → Atlas 的"稳定前缀"是真实的增量轴。
4. **formal_reasoning 域的环境自带 Compress / Revise 工具**（附录 A.1 的 prompt 原文），该域压缩是 agent 显式调用；其余四域 prompt 无这些工具，压缩由包装器在子任务边界触发。**Atlas 接入时两域行为不同，要分别处理。**
5. 摘要质量完全依赖 agent 自己生成（m 是参数），无外部校准 → 摘要失真是 MAGE 自身的残余风险。

## 2. 实验设置（M1/M3 可直接复用的口径）

- **域与规模（Table 5，合计 701 任务）**：Shopping 150 任务/均 98.6 步；Travel 270/237.4 步；Search 221/82.0 步；Math 40/24.7 步；Physics 20/13.8 步。Search 域轨迹最长（均 101.9K token）。
- **模型**：Qwen3.6-27B + ReAct；嵌入 Qwen3-8B-Embedding；vLLM 0.20.0 / A100 / Python 3.12。附录 B 给了 Qwen3.6-35B-A3B、Gemma4-31B 在 Shopping 域的结果——**换后端报数有先例可引**（Atlas 用不同模型时照此办理）。
- **指标**：SR（Shopping/Travel 要求全部子任务全对；Search/Math/Physics 由最后一子任务定胜负）、PS（完成子任务比例）、每任务总 token（prompt+生成）。
- **基线协议（A.2，Atlas 接入照抄）**：每任务开始存储清空 → 每个子任务结束后把完整交互轨迹经 `Update` 写入存储 → 每个动作前用"当前子任务轨迹"作 query 调 `Retrieve`，把结果拼进上下文。
- **基线 SR 速查（顺序：Shopping / Travel / Search / Math / Physics）**：
  - Long Context：33.3 / 5.2 / 48.4 / 40.0 / 65.0
  - HippoRAG2：20.7 / 9.6 / 36.2 / 45.0 / 60.0（Search 域 token 反而比 long-context 低 38.5~68.2%）
  - Mem0：19.3 / 2.6 / 35.3 / 40.0 / 55.0
  - Mage：**39.3 / 15.2 / 56.6 / 42.5 / 65.0**（token 全域降 32.9~71.4%）
- Mage vs long-context 汇总：SR 平均 +7.8pp、PS +8.7pp。

## 4. 对 Atlas 十项决策的校验与风险

- **#1 图承载 vs 树承载**：论文所有失败案例（Fig 2）指向语义检索的状态碎片化与错误污染，不针对"无树的图承载"。Atlas 的 active-only 读取在防污染上比 MAGE 更硬（查询层结构过滤 vs 树结构隔离）。**风险**：放弃 Revise 的树回滚，错误恢复改由决策变迁+H 提示承担，而消融显示 Revise 值 4~5pp——M3 类型学统计要专门盯"错误恢复类"违规占比。
- **#2 结转触发**：与 Compress 触发逻辑一致 ✓。差异点（我们的增量）：MAGE 压缩时状态随摘要走；Atlas 结转时状态**先结构化入图**、摘要只管叙事——结转器要产出双产物（图写入 + 带步号叙事摘要）。
- **#3 查账**：Maintain 消融 −5.2~−6.7pp 是"纯规则查账"必须正面回应的数字。辩护逻辑：MAGE 摘要是状态唯一载体，校验的是状态本体；Atlas 摘要只管叙事、状态在图且有"活跃 Constraint/Decision 缺席即报错"兜底——校验对象已消失。**留 revisit 触发条件**：M3 若"摘要叙事失真导致违规"占比高 → 升级为阶段级 LLM 校验（决策 #3 选项 C）。
- **#4 组装**：MAGE 无显式预算配比（C 随子目标数自然增长、R 受阈值、H 是指针集合）→ 动态预算四区是细化增量，"固定配比作对照"的消融设计成立。
- **#5~#7**：论文无多智能体内容，无冲突、无输入。
- **#8 简化复现可行性 ✓**：复现目标 = 子任务边界的 LLM 摘要压缩（无树、无 Maintain、无 Revise）。在 A.2 协议下就是一个普通 memory 基线：Update = 追加轨迹并在子任务边界生成摘要、清近期区；Retrieve = 返回 C+R。实现成本低。
- **定位语（面试线）**：HippoRAG2 同为"图"，但图用于**检索**（PageRank 按相似度捞三元组）；Atlas 图用于**承载状态**（读按结构、只取 active、写入即治理）——同构不同纪律。
- **域难度预警**：Travel 全场最高 SR 仅 15.2%；Physics 上 Mage 与 long-context 打平（65.0），Math 仅 +2.5pp——**formal_reasoning（M2 目标域）是全场最难拉开差距的域**。反过来说：若图状态承载在该域有效，说服力也最强。M2 目标"胜过 long_context 对照"要按这个现实校准预期。
