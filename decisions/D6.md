## D6 · 锚点口径修订：EM/F1 是主锚，token 只记录不设阈值（修订 D1 的一部分）

- **事实：** 同一配置（naive）、同题集、同代码路径重跑，`prompt_tokens` **逐题逐字节一致**（如 2hop__10114 两版都是 1442），EM 0.300 完全复现；但 `completion_tokens` 从 1674 掉到 486、token/题 从 3927 掉到 2162。
- **原因：** 差异全部来自**空答案重试**——旧跑空答率 10%、重试率 36%、均调用 1.56；新跑空答率 0%、重试率 16%、均调用 1.16。重试一旦触发就按 2048/4096 预算再发一次，把 completion 拉高。同一模型（deepseek-v4.1-flash）在不同时间的思维链长度变了，这是**服务端行为漂移**，不是代码行为变化。
- **决定：** `D1` 的锚点改为 **EM 0.300 + F1 0.42±0.02 + 逐题 prompt_tokens 一致**；`token/题` 与 `空答率` 作为**环境相关指标记录在 manifest/报表里**，不作为"重构合格"的判据。
- **代价：** 简历与文档里引用 token 时必须注明运行日期与空答率；跨时间比较 token 要谨慎。
